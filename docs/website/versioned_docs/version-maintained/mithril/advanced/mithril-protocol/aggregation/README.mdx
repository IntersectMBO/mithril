This section details the different ways the Mithril protocol can aggregate the signatures.
The aggregation of signatures is the core of the Mithril protocol.
It consists in verifying the signatures received by the aggregator and packing them into the Mithril [multi-signature](../../../../glossary.md#multi-signature) that is easy and fast to verify.

Here is a summary of the differences between the aggregation flavors with regards to the proof size:

|                                             | Concatenation                      | Non-recursive SNARK                             | Recursive SNARK                                                 |
| ------------------------------------------- | ---------------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| **Size**                                    | ~150KB                             | ~4KB                                            | ~13KB                                                           |
| **Signature scheme**                        | BLS                                | Schnorr                                         | Schnorr                                                         |
| **Hash function**                           | Blake2b                            | Poseidon                                        | Poseidon                                                        |
| **Aggregation**                             | Cheap                              | Expensive                                       | Expensive                                                       |
| **Verification**                            | Fast                               | Fast                                            | Fast                                                            |
| **One certificate verifies the full chain** | No                                 | No                                              | Yes                                                             |
| **Implementation maturity**                 | Stable                             | Unstable                                        | Unstable                                                        |
| **Pros**                                    | Maturity and low proving costs     | Small size                                      | Small size and constant-cost verification of the entire history |
| **Cons**                                    | Size and linear growth with epochs | High proving cost and linear growth with epochs | High proving cost                                               |
